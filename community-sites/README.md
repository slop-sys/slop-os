# Community Sites: Secure Contribution Model

This folder defines a secure way to let people submit Microslop Explorer sites while protecting trusted SlopOS code.

## Goal

Allow community site submissions without letting untrusted contributors modify:
- app runtime code
- browser routing logic
- quest logic
- anything executed in trusted origin context

## Recommended Architecture

1. Keep this repository as the trusted runtime (SlopOS app code only).
2. Use a separate community repository for submissions.
3. Accept only data-driven submissions (manifest + optional static assets).
4. Validate everything in CI.
5. Import only approved submissions into a generated catalog.
6. Render user content in a sandboxed iframe or via trusted templates.

## Why Separate Repos

- Clear trust boundary.
- Main repo permissions stay tight.
- Contributors only touch submission repo.
- Easier branch protection and required review policy.

## Security Rules (Hard Requirements)

1. Do not execute user-submitted JavaScript in SlopOS origin.
2. Disallow inline event handlers and script tags in submission HTML.
3. Disallow javascript: URLs.
4. Restrict iframe sandbox capabilities.
5. Restrict allowed protocols to https only (except slop:// internal links generated by trusted code).
6. Keep file-size and count limits to prevent abuse.
7. Require maintainer approval before publishing.

## Files In This Folder

- community-site.schema.json: JSON schema for site submissions.
- examples/site.valid.json: example valid submission manifest.
- templates/community-repo/: starter files for the public submissions repo.
- templates/main-repo/: starter workflow for safe sync into this repo.

## Suggested Rollout

1. Use the public submissions repo: `https://github.com/slop-sys/community-pages`.
2. Copy templates/community-repo contents into it.
3. Enable branch protection and required checks.
4. For public repo sync, no secret is required for archive download; use a token only if you need higher API rate limits.
5. Copy templates/main-repo workflow into this repo only when ready.

## Current Repo Wiring

- Community submissions repo: `slop-sys/community-pages`
- Trusted runtime repo: `slop-sys/slop-os`
- Sync workflow template already points at `slop-sys/community-pages`.

## Hosting Compatibility (GitHub Pages)

This model works with GitHub Pages because:
- All content is pre-validated and statically published.
- No server-side runtime is required.
- Publication happens through CI-generated JSON artifacts.
